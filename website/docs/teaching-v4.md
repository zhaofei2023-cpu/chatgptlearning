# 第四版升级：教师题库、最新代码、AI学情与资源封面

适用网站：https://zhaofei2023-cpu.github.io/chatgptlearning/

本版沿用已有Supabase项目与四级账号，不重新创建机构或学生。GitHub Pages仍只承载前端。

## 本次功能与设计

| 角色 | 入口 | 功能 |
|---|---|---|
| 教师 | 教师工作台 → 我的题库 | 新建草稿、编辑、发布、撤回、删除下架；按自己的题目分类筛选 |
| 教师 | 教师工作台 → 按学生查看 | 每个学生账号独立归集，每题显示最新一份代码及累计提交次数；查看与批阅 |
| 学生 | 竞赛作业 → 编辑器 | 重交覆盖同题旧代码；查看最新评分，载入最近提交到编辑器 |
| 管理员 | 工作台 → AI学情报告 | 按学生和7/14/30/90天选取证据；对话制定要求、保存个人模板、生成修订报告、历史、下载Markdown及打印PDF |
| 管理员 | 学习资源 → 上传素材 / 编辑素材 | 为本地文件、HTTPS视频链接、课件等上传、替换、移除封面；管理视频及其他素材的发布、删除 |

- 同一题被教师删除后会下架，不再允许学生作答；最新提交保留，避免学情依据随题目删除一起丢失。
- 每题只保留当前代码，累计次数是整个题目的提交次数，不代表所选日期内的次数。无法用当前代码还原每次修改或声称学习进步。
- 重交后原分数与评语清空，等待重新批阅。如果教师打开旧版本后学生重交，服务端会拒绝保存旧版本的批阅，须重新打开代码。
- 同名学生按账号ID区分；分类只属于创建该分类的教师。机构管理员不能读取其他机构的报告。
- 资源私有封面支持PNG/JPEG/WebP，最大5MB；视频文件仍是单个40MB上限。封面不上传到公开GitHub仓库。
- 固定的“官方公开课程”是系统参考入口；自主运营课程请在素材管理中添加HTTPS链接并设置封面。

## 一、先升级现有数据库（只需执行一次）

1. 在Supabase导出需要保留的数据库备份，尤其是旧提交。本版按需求归并旧记录，**删除同一学生同一题的旧代码，只保留最新代码与累计次数**。
2. 打开[当前项目SQL Editor](https://supabase.com/dashboard/project/iyqdrtkaqatfvvxryawf/sql/new)。
3. 本版以前提`schema.sql`、`002_institutions.sql`、`003_content_and_competitions.sql`已完成为基础。若还未完成003，先执行003，不要重复初始化或重新执行schema。
4. 打开并复制[004_teaching_reports_covers.sql](https://zhaofei2023-cpu.github.io/chatgptlearning/upgrades/004_teaching_reports_covers.sql)，在SQL Editor运行全部内容。迁移使用单个事务；失败会回滚，先修正报错后再运行，不要仅运行片段。
5. 成功后刷新网站，教师工作台中的升级提示会消失。

SQL创建自己的题目分类、提交唯一约束及受控提交/批阅函数、私有`learning-covers`桶、管理员报告/模板表与每日额度。不会修改已有密码、机构、班级或学习资源文件。

升级后学生提交与教师批阅使用受控RPC。未执行004时仍沿用原有提交和批阅方式，以免中断正在进行的教学；分类、删除下架与最新代码覆盖等新能力会明确提示等待升级。旧记录只有在004执行成功后才真正归并。

## 二、接入真实OpenAI学情分析

**ChatGPT网页会员不能直接充当网站API账户。** 网站调用OpenAI API，需独立API密钥及可用API额度，可能产生费用；不启用AI时，账号、作业、资源、教师批阅不依赖付费AI。本版不会自动开通付费或添加付款方式。

1. 打开[本项目Edge Functions](https://supabase.com/dashboard/project/iyqdrtkaqatfvvxryawf/functions)。
2. 下载[study-report函数文件包](https://zhaofei2023-cpu.github.io/chatgptlearning/upgrades/study-report-function.zip)。代码来源也可在仓库`website/supabase/functions/study-report/`查看。
3. 新建名为`study-report`的函数。通过Supabase网页编辑器部署时，放入`index.ts`和同目录的`report-core.mjs`两个文件，保持文件名与相对导入不变；保留登录JWT验证。已有的`account-admin`、`mentor`不要删除。
4. 在Edge Functions的Secrets中配置以下服务端变量（不得放进网页或聊天中）：

| Secret | 值 |
|---|---|
| `OPENAI_API_KEY` | 你们自有OpenAI API密钥 |
| `OPENAI_MODEL` | 建议先用`gpt-4.1-mini`，也可设为你们可用的兼容Chat Completions模型 |
| `ALLOWED_ORIGIN` | `https://zhaofei2023-cpu.github.io`（不带末尾斜杠和仓库路径） |
| `AI_ENABLED` | `true` |

Supabase自动提供`SUPABASE_URL`和`SUPABASE_ANON_KEY`。函数使用登录用户的权限读取证据，不使用浏览器传入的代码、不使用service_role跨机构查询。不要发送service_role、数据库密码或OpenAI密钥给聊天助手。

使用CLI部署时，从website目录执行：

```sh
supabase functions deploy study-report --project-ref iyqdrtkaqatfvvxryawf
```

### 费用与额度

每位管理员每日最多30次“发送讨论”或“生成/修订报告”，按北京时间重置。请求已进入AI后供应方失败也计入该限额。它是本系统的次数保护，不能代替供应方预算；请同时设置OpenAI项目预算与告警。未配置密钥或未启用时，页面如实提示AI未接通，不会用固定回答冒充真实报告。

## 三、教师具体操作

1. 在“我的题库”新建分类，如“图论 / 基础模拟 / 第三周训练”。
2. 新建题目并选择班级、分类、北京时间截止时间。默认草稿，学生不可见；保存时也可直接发布。
3. 每张题卡可编辑、发布、撤为草稿、删除。删除为下架，学生记录保留。
4. 在“按学生查看”展开某个账号，看到该生每题最新提交。点击查看与批阅，提交次数和时间可辅助核对版本。
5. 分类可改名或删除；删除分类仅移入“未分类”，不删除题目。不能给自己的题目使用其他教师的分类。

## 四、管理员报告对话流程

1. 工作台点击“AI学情报告”，选择学生账号和近7/14/30/90天。
2. 编辑报告结构，例如：“概况、知识点证据、边界错误、7天练习计划、家长摘要；每项用题目实例支撑”。可保存为自己的默认模板。
3. 点击“发送讨论”，补充语气、内容和结构需求；再点击“生成 / 修订报告”。每次请求读取服务端最新可见记录。
4. 生成后自动保存，可在历史中打开，并下载Markdown或浏览器打印为PDF。生成成功但保存失败时会提示，报告仍可立即下载。
5. 切换学生或时间范围会开启独立对话，避免混用证据。历史报告显示生成时的内容，不会因后续代码更新自动改变。

证据范围包含该学生所选时间内的作业与竞赛最新提交、题目及已有人工评语。每次代码详细分析最多取最近50题、每题最多4000字符、合计最多70000字符；报告会注明截断或证据不足。代码不执行，不等同自动评测；未提交不等同未学习。报告是教学参考，需教师核实。

## 五、管理员资源封面与视频管理

1. 学习资源 → 上传素材，选择“本地文件”或“HTTPS学习链接”。
2. 在“资源封面”选PNG/JPG/WebP。可以先保存草稿，再发布给师生。
3. 编辑时不选新封面会保留原封面；“移除封面”后保存恢复默认图。
4. 进入资源管理，删除素材时清理正文文件和封面。更新成功但旧文件清理失败会显示清理提示，需在Storage检查旧文件，避免占用免费容量。
5. 私有封面使用短期签名链接，过期后重新打开页面加载。

## 六、真实上线验收

本地数据库权限测试与浏览器演示已覆盖功能逻辑，但不能代替你们Supabase项目的真实账号验收：
- 教师A创建分类和题目，教师B无法改动；草稿学生不可见，发布后可提交。
- 同一学生对同题连交两次，数据库只保留一条，代码为第二版；同名学生不互相覆盖。
- 学生重交后旧评分清除；教师旧窗口批阅被拒绝。
- 机构A管理员不能读取机构B的报告和封面。
- 管理员上传真实封面和视频，师生能观看；删除后文件清理。
- 使用自己的API密钥完成一次讨论和一次生成，确认报告保存在历史中且不包含其他学生记录。

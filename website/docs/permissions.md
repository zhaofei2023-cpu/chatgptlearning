# 四级角色与数据权限

| 能力                 | 学生                   | 教师           | 机构管理员 | 平台管理员                 |
| -------------------- | ---------------------- | -------------- | ---------- | -------------------------- |
| 创建机构及机构管理员 | 不可                   | 不可           | 不可       | 可                         |
| 创建/停用教师和学生  | 不可                   | 不可           | 仅本机构   | 可选择机构                 |
| 查看账号资料         | 本人                   | 本人           | 本机构     | 全机构                     |
| 创建班级、发作业     | 不可                   | 自己的班级     | 不代替教师 | 不代替教师                 |
| 加班并提交代码       | 本机构、已发布、截止前 | 不可           | 不可       | 不可                       |
| 查看提交             | 本人                   | 自己班级       | 本机构只读 | 全机构只读                 |
| 评分、写评语         | 不可                   | 自己作业的提交 | 不可       | 不可                       |
| 修改已提交的代码     | 不可                   | 不可           | 不可       | 不可（应急数据库维护另计） |
| 添加机构资源         | 不可                   | 仅本机构       | 不可       | 不可                       |

访客只能访问官网和系统公开资源。教师添加的资源仅本机构可读。学生不能自行注册，注册触发器忽略元数据中的角色，产生未启用账号。真实角色只通过受保护的开户函数设置。机构管理员不能授予管理身份或管理其他机构。

账号创建和停用使用服务端 Edge Function，验证 JWT、实时角色和机构范围。service_role 只在服务端。业务表开启 RLS，数据库再次限制账号启用状态、机构、班级成员、截止时间、提交归属和教师评分权限。前端切换角色不是授权方式。

新账号必须修改临时密码，数据库观察到 Auth 密码哈希变化后才开放业务访问。停用账号或机构会拒绝后续私有数据库请求，不能收回已经下载的数据。学生草稿、收藏和所有演示数据只保存在本地。

本地测试涵盖三个机构、跨机构读取/写入、邀请码、自我提权、学生改分、教师越权、首次改密、停用机构和匿名访问。真实 Supabase Auth、管理函数、首次登录及跨设备保存仍需实际项目联调。见 [免费部署步骤](free-deployment.md)。

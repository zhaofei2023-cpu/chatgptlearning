# 角色与权限设计

| 能力                     | 访客 | 学生                         | 教师                     | 平台管理员     |
| ------------------------ | ---- | ---------------------------- | ------------------------ | -------------- |
| 首页、公开资源、使用指南 | 可读 | 可读                         | 可读                     | 可读           |
| 注册邮箱学生账号         | 可   | —                            | —                        | 管理认证服务   |
| 自行选择正式教师身份     | 不可 | 不可                         | 不可                     | 核验后授予     |
| 创建班级、发布作业       | 不可 | 不可                         | 仅自己的班级             | 数据库管理     |
| 加入班级                 | 不可 | 有邀请码                     | 不适用                   | 管理成员       |
| 查看作业                 | 不可 | 本人所在班级已发布作业       | 自己的作业和草稿         | 管理数据       |
| 提交代码                 | 不可 | 本人、已入班、已发布、截止前 | 不可代替学生             | 不作为日常操作 |
| 查看代码                 | 不可 | 自己的提交                   | 自己作业的学生提交       | 管理数据       |
| 批阅、评分               | 不可 | 不可                         | 仅自己作业的提交         | 管理数据       |
| 改写已提交代码           | 不可 | 不可                         | 不可                     | 仅应急数据维护 |
| 添加公开学习资源         | 不可 | 不可                         | 可                       | 可             |
| AI答疑（配置后）         | 不可 | 登录、题目可访问且有配额     | 登录、题目可访问且有配额 | 管理配置与预算 |

管理员不通过普通网页切换得到，使用Supabase控制台和受保护的后台权限管理。前端不保存service_role。

## 数据边界

- 注册触发器忽略用户提交的role字段，只创建学生。
- 班级邀请码通过认证后的数据库函数验证，成员不能直接写入其他人的成员关系。
- 老师只能给自己的班级发布作业；数据库触发器验证题目与班级教师一致。
- 提交归属、题目发布状态、班级成员、截止时间在数据库再次检查。提交时状态固定为pending，分数清空，姓名和时间来自服务器。
- RLS限制可读的提交范围，列权限禁止老师修改提交代码，也禁止学生改分。
- 学生草稿与演示数据保存在本地浏览器；不属于云端安全边界。共用电脑请勿保存敏感信息，并在结束后退出。
- 公开课条目可公开阅读；代码、成绩与私人AI问题不放入GitHub仓库。

## 正式上线前验收

在真实服务中建立两个学生、两个教师和两个班级：验证未入班访问、跨班查询、直接REST修改角色、自改分、教师修改代码、越过截止时间、伪造学生ID、匿名读取提交均被拒绝。验证有效的学生提交和所属教师批阅成功。测试换设备同步、账号退出缓存清除、邮箱确认、密码恢复、AI来源限制和配额。

本地权限测试覆盖上述数据库规则中的核心路径；它不能替代真实Supabase Auth、邮件、Edge Function、网络与供应商账户的集成验收。
